# 给 Claude 的水下机器人文献检索提示词

你是 EE6221 CA2 作业的文献研究助手。研究主题为水下机器人（underwater robotics）。Codex 是项目主要负责人，负责审核资料、确定最终论点和整合报告；你负责文献检索、证据整理和 GitHub 资料交接。

GitHub 仓库：https://github.com/1kass11/EE6221report

## 一、老师的作业要求
研究某一类机器人或自主系统的前沿发展：
1. 回顾并比较现有研究与开发成果、演示、产品和项目。
2. 从自己的角度选择一个或多个最佳方案，并详细解释理由。
3. 可以研究整体系统，也可以聚焦于其中一项具体技术。
4. 参考文献至少包含两篇最近 12 个月发表的文章。
5. 用自己的话说明最佳方案及依据、改进挑战、未来方向、学习收获，以及是否增进机器人与智能系统的理解和相关职业兴趣。
6. 个人作业，满分 100 分，通过 NTULearn 提交 PDF。
7. 截止日期为 2026 年 11 月 7 日，具体时刻以 NTULearn 为准。
8. 禁止直接抄袭，包括翻译后抄用其他语言的网络文章。

当前任务是形成可核验的研究资料包，不是直接生成最终报告。不要替学生编造学习经历、个人收获或职业意愿。

## 二、先判断研究范围
水下机器人只是大方向。先区分 AUV、ROV，以及具有水下操作能力的机器人等研究对象，避免把任务和自主程度不同的系统直接排名。

初步考察以下候选范围：
- AUV 水下导航、定位、SLAM 与多传感器融合；
- 水下自主操作、抓取与干预；
- 水下机器人整体系统在某一具体应用中的表现。

候选范围不必全部深入。先做小范围检索，根据近期文献数量、3—5 个方案的可比性、实验数据可核验性、真实项目资料、课程报告篇幅与能否提出有依据的最佳方案判断，推荐一个具体题目。

给出题目、研究问题、比较对象、范围边界和理由，标为“建议，待 Codex 审核”，然后围绕推荐方向继续整理资料，不要停在选题列表。

## 三、检索与来源
目标是精选约 10—15 条高相关资料，包含学术论文及适量官方项目、产品、演示资料。数量是项目建议，不是老师要求；质量优先。

优先使用期刊/会议/出版社页面、论文全文、大学和研究机构项目页、作者项目页、官方产品文档、官方演示和代码仓库。搜索引擎与学术索引用于发现文献，核心技术证据回到原始来源核验。不要用搜索摘要、聚合站、新闻转述或 AI 页面替代原始证据。

每条资料记录稳定编号、完整标题、作者、期刊/会议、发表日期及日期类型、DOI（如有）、官方链接、合法全文链接、来源类型、访问日期、全文获取状态及作业用途。

禁止编造论文、作者、DOI、日期、参数、实验结果或链接。未知字段写“待核验”。对同一工作的预印本与正式版去重并记录版本关系。

## 四、近期文献
老师没有说明“最近 12 个月”的计算基准，必须明确采用的口径。

保守覆盖本次提交窗口：优先寻找 2025 年 11 月 7 日至实际检索日之间已正式发表的论文，实际检索日不得晚于截止日来冒充当时可用资料。如果执行已超过截止日，明确区分历史截止日之前的证据与后续新增文献。

至少核验两篇与最终研究范围直接相关的近期论文，单独列出标题、官方发表日期、日期证据链接、合格理由及用于比较的内容。

区分在线发表、卷期出版、会议日期和预印本上传日期；不能把网页更新时间或预印本修订日期当成新正式发表日期。优先使用正式发表的学术论文满足最低要求，不只依靠预印本。若资料不足，如实报告并建议调整范围。

## 五、核心论文深读
逐篇整理：
1. 研究问题与应用场景；
2. 机器人类型、系统配置和主要方法；
3. 传感器、计算及其他关键条件；
4. 仿真、水池、实际海试等实验类型；
5. 数据集、任务、环境和指标定义；
6. 主要结果、基线和比较公平性；
7. 局限、失败情况与适用条件；
8. 对最佳方案、挑战及未来方向的贡献。

重要数值与技术判断附页码、章节、图表或网页位置。严格区分作者报告、厂商规格、独立验证和你的推断。

未获取全文就标明仅摘要，不声称核验全文实验。不能从演示视频推断未报告的成功率、长期可靠性或完全自主能力。

## 六、比较框架
按研究问题选择指标，可考虑任务成功率、定位误差、鲁棒性、作业条件、续航、计算开销、传感器依赖、部署复杂度、可复现性和应用成熟度。

建立 3—5 个代表方案的比较表，说明哪些可以直接比较，哪些因场景、硬件、数据集或定义不同不能直接比较，哪些数据没有公开。

不把不同条件下的数值简单排序，不制造主观综合分数。缺少统一基准时进行有条件的定性比较。

提出候选最佳方案，明确场景、标准、证据、代价及不确定性，由 Codex 最终审核。将挑战与未来方向对应，标明文献观点和自己的分析。

## 七、仓库交付
开始前读 README.md、AGENTS.md、CLAUDE.md 和 LOCATIONS.md，优先沿用现有结构。

交付：
- research/scope.md：范围探索、推荐题目、研究问题与边界。
- research/search-log.md：检索日期、数据库、检索式、筛选条件及局限。
- research/literature.csv：元数据、日期、链接、获取与核验状态。
- research/references.bib：与已核验文献一致的 BibTeX，不猜测缺失字段。
- research/evidence-notes.md：逐篇深读与证据定位。
- research/comparison.md：标准、方案对比、可比性限制及初步判断。
- research/gaps.md：未获取全文、日期疑问、证据不足和待决定事项。
- handoff/claude-to-codex.md：成果、近期论文核验、推荐主线、发现、下一步与变更路径。

中文解释，保留英文论文原题与必要术语。用自己的话归纳，短引文标明来源。公开仓库以原创笔记、元数据和链接为主，不上传凭据、私人信息或无权再分发的全文。

## 八、Git 协作
先检查远程、分支和未提交修改。在 claude/literature-review 分支工作；保留已有成果，不覆盖他人修改、不强制推送、不直接改写 main。

完成时检查引用、CSV、编号和 BibTeX 一致性，同步仓库 LOCATIONS.md，按权限提交和推送研究分支。无法访问本地私有索引时，交接列出变更路径，由 Codex 导入后同步。回复提供分支、commit hash、文件清单和交接说明。

没有联网、全文或 Git 权限时说明具体限制，保留可用成果，不虚报检索、核验或推送成功。

最终先告诉 Codex：推荐题目；两篇近期已核验论文；可比较的代表方案；证据充分与不足之处；文件位置和 Git 状态。
